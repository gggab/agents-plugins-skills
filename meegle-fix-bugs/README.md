# Meegle Bug Fix

`meegle-fix-bugs` 用于处理飞书项目中的 Bug。它要求先读取证据并复现问题，再进行本地修复和验证；共享状态变更仍需明确授权，但可以把提交、推送、部署和飞书回写一次性列清后合并授权，不重复索要口令。

## 依赖

- 飞书项目 Meegle：用于查询 Bug、读取上下文和回写结果，每位使用者通过自己的账号完成 OAuth。
- `gitlab_deployment`：用于查询 Pipeline 和执行经过批准的部署；仅修复本地代码时可以不连接。
- Bug 对应的本地代码仓库：请在实际要修复的项目中启动 Codex，不要在本插件目录中执行修复。

不要共享 OAuth、Token 或其他凭证。

## 安装

先按照[仓库说明](../README.md)添加 `standard-smart-office` Marketplace，然后安装：

```text
codex plugin add meegle-fix-bugs@standard-smart-office
```

安装后需要新建 Codex 任务或 CLI 会话，才能加载插件中的技能。

## 快速开始

第一次使用建议从只读查询开始：

```text
使用 $meegle-fix-bugs 查询飞书项目中分配给我的所有未完成 Bug。
只列出 ID、优先级、状态和标题，不修改任何数据。
```

选择一个 Bug 后，先要求复现：

```text
使用 $meegle-fix-bugs 处理 Bug ABC-123。
读取描述、评论和附件并复现问题，只诊断，不修改代码。
```

确认问题后允许本地修复：

```text
修复 Bug ABC-123。允许修改本地代码并运行测试，
但不要提交、推送、部署或更新飞书项目。
```

## 分阶段授权

插件不会把“修复”“继续”或“全部完成”理解为所有操作都已获得授权。需要执行下一阶段时，请明确说明：

| 阶段 | 示例提示词 |
| --- | --- |
| 提交 | `提交 Bug ABC-123 的改动，一个 Bug 一个 commit，不要推送。` |
| 推送 | `推送 Bug ABC-123 的提交，但不要部署。` |
| 查询部署 | `检查该提交是否部署到 jv26，只查询，不触发部署。` |
| 部署 | `展示项目、Pipeline、完整 SHA、Job 和环境，等我批准后部署到 jv26。` |
| 飞书回写 | `部署成功后更新 Bug 状态和必填字段，添加简洁的中英文双语修复评论并读取确认。` |

也可以一次性授权剩余闭环：

```text
提交并推送这些 Bug；准备部署到 jv26 时列出项目、Pipeline、完整 SHA、Job、环境和拟回写的飞书字段，等我一次确认。部署成功后按该方案更新状态、添加简洁的中英文双语评论并回读，不要再次询问。
```

项目范围选择和 Pipeline/Job 查询都是只读操作，不需要批准。部署前，插件会展示准确的项目、分支、Pipeline、提交 SHA、Job、目标环境及拟回写值；只保留一次目标部署批准，不再要求 `CONFIRM PROJECT SCOPE`、`DEPLOY APPROVED` 等固定口令。部署成功不等于 Bug 已关闭；飞书状态、字段和评论写入后仍会重新读取验证。

同一连续任务中，当前账号、飞书项目和字段元数据只解析一次。除非任务恢复、连接重建、账号或项目变化，或真实调用返回认证错误，否则不会在每个阶段重复执行 OAuth/账号检查；写入前仍会读取 Bug 当前状态和合法流转。

修复评论使用中英文双语短句；Verification 只保留测试/构建结果，以及部署环境、完整 SHA 和状态。

## 工作原则

- 一个 Bug 对应一个提交，不混入无关文件。
- 缺少复现信息时停止修改，并明确列出需要补充的内容。
- 本地测试失败、部署 SHA 不一致或部署失败时，不关闭 Bug。
- 只根据当前飞书项目元数据填写状态、分类、解决结果和人员，不猜测枚举值。
- 分别报告本地修改、提交、推送、部署和飞书回写状态。

完整执行规则位于 [`skills/meegle-fix-bugs/SKILL.md`](./skills/meegle-fix-bugs/SKILL.md)。
